Les éléments importants de k6

Virtual Users

Les VUs simulent plusieurs utilisateurs qui exécutent le même scénario en parallèle.

Scénarios

Un script décrit ce que fait l'utilisateur : appel HTTP, authentification, navigation ou API.

Thresholds

Les thresholds définissent des critères de réussite, par exemple : p95 < 500 ms.

Métriques

k6 mesure notamment la latence, les requêtes par seconde, les erreurs et la durée des requêtes.

Automatisation

Les tests peuvent être intégrés dans GitHub Actions, GitLab CI, Jenkins ou d'autres pipelines.

Scripts JavaScript

Les scénarios k6 sont écrits en JavaScript, ce qui rend les tests lisibles et faciles à versionner.

Choisir un type de test

Smoke Test Load Test Stress Test Spike Test

🔥 Smoke Test

Vérifie rapidement que le script et l'application fonctionnent correctement avec une charge très faible.

Exemple : 1 à 2 VUs

📈 Load Test

Vérifie le comportement de l'application sous une charge normale ou attendue en production.

Exemple : 20 à 100 VUs

💥 Stress Test

Augmente progressivement la charge pour découvrir les limites du système et son point de saturation.

Objectif : trouver le breaking point

⚡ Spike Test

Simule une montée extrêmement rapide du trafic afin d'observer comment l'application réagit à un pic soudain.

Exemple : 10 → 500 VUs brutalement

Exemple de commande

k6 run --vus 10 --duration 30s script.js
